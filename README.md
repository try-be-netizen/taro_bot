# 🔮 Tarot Bot — канал «Карта недели» + WebApp

Telegram-канал с еженедельным раскладом из 3 карт + ежедневные факты о Таро.
Раскрытие карты происходит во встроенном Telegram WebApp на GitHub Pages.

## Что включает

| Файл | Назначение |
|---|---|
| `webapp/index.html` | WebApp — страница с тремя картами и анимацией выбора |
| `webapp/predictions.json` | Текущие предсказания недели (обновляется ботом) |
| `webapp/cards.json` | Справочник 78 карт Райдера-Уэйта |
| `bot/generate_predictions.py` | Генерация предсказаний через Groq, раз в неделю |
| `bot/weekly_post.py` | Публикация еженедельного поста в канал |
| `bot/daily_fact.py` | Ежедневный факт о Таро |
| `.github/workflows/generate.yml` | Cron в воскресенье 22:00 МСК — генерация |
| `.github/workflows/weekly.yml` | Cron в понедельник 9:00 МСК — пост в канал |
| `.github/workflows/daily.yml` | Cron каждый день в 11:00 МСК |

## Архитектура

```
Понедельник 9:00 МСК
    │
    ├─ generate_predictions.py
    │     ↓ Groq API (бесплатно)
    │     ↓ выбирает 3 карты
    │     ↓ генерирует тексты
    │     ↓ обновляет webapp/predictions.json
    │
    ├─ weekly_post.py
    │     ↓ рисует коллаж 3 закрытые карты
    │     ↓ постит в Telegram-канал
    │     ↓ кнопка "🔮 Открыть карту" → WebApp
    │
    └─ commit predictions.json → GitHub
            ↓
            ↓ GitHub Pages автодеплой
            ↓
       Пользователь жмёт кнопку
            ↓
       Открывается webapp/index.html
            ↓
       Видит 3 закрытые карты
            ↓
       Тапает одну → переворот → предсказание
```

Каждый день в 11:00 МСК — отдельный пост с фактом о случайной карте.

## Пошаговая настройка

### Шаг 1. Создай репозиторий на GitHub

Назови как хочешь, например `tarot_bot`. Сделай публичным (для бесплатных GitHub Pages).

### Шаг 2. Залей файлы

Через **Add file → Upload files** загрузи:
- `webapp/cards.json`
- `webapp/predictions.json`
- `webapp/index.html`
- `bot/generate_predictions.py`
- `bot/weekly_post.py`
- `bot/daily_fact.py`
- `bot/requirements.txt`

Через **Add file → Create new file** создай (имя со слешами — папки создадутся сами):
- `.github/workflows/generate.yml` — вставь содержимое из `generate.yml`
- `.github/workflows/weekly.yml` — вставь содержимое из `weekly.yml`
- `.github/workflows/daily.yml` — вставь содержимое из `daily.yml`

### Шаг 3. Подними GitHub Pages

1. Settings → Pages
2. Source: **Deploy from a branch**
3. Branch: **main** / **/ (root)**
4. Save

Через 1-2 минуты сайт будет доступен по адресу:
```
https://<твой_логин>.github.io/<имя_репо>/webapp/
```

Проверь что открывается — должно показать три карты с обложками.

### Шаг 4. Создай Telegram-бота и Mini App

1. Напиши `@BotFather` в Telegram
2. `/newbot` → задай имя и username (например `my_tarot_bot`)
3. Сохрани токен
4. **Привяжи Mini App** — это критически важно для работы кнопки в канале!
   - В @BotFather: `/newapp`
   - Выбери своего бота
   - Title: `Карта недели` (или как захочется)
   - Description: краткое описание
   - Photo: загрузи любую картинку 640×360 (можно `webapp/back-trio.jpg`)
   - Demo GIF: можно пропустить
   - **Web App URL**: вставь `https://<твой_логин>.github.io/<имя_репо>/webapp/`
   - Short name: например `tarot` (это короткое имя для url)

После этого получишь ссылку вида `https://t.me/my_tarot_bot/tarot` — это и есть **direct link**, который ты должна положить в секрет `WEBAPP_URL`.

### Шаг 5. Создай канал и добавь бота админом

Канал может быть приватным или публичным. Бота надо назначить администратором с правом постить сообщения.

Узнай **chat_id** канала:
- Если публичный — это `@название_канала`
- Если приватный — отправь любое сообщение в канал, форварднь его боту `@userinfobot`, тот покажет ID вида `-100xxxxxxxxxx`

### Шаг 6. Получи API-ключ Groq

1. Зайди на https://console.groq.com (можно через Google)
2. API Keys → Create API Key
3. Сохрани ключ

Бесплатный лимит — 14 400 запросов в день модели `llama-3.3-70b-versatile`. Нам нужно ~10 запросов в день. С большим запасом.

### Шаг 7. Задай секреты в GitHub

Settings → Secrets and variables → Actions → New repository secret. Создай 4 секрета:

| Имя | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от BotFather |
| `TELEGRAM_CHAT_ID` | `@название_канала` или `-100xxxxxxxxxx` |
| `WEBAPP_URL` | `https://t.me/<bot_username>/<app_short_name>` (НЕ ссылка на github.io!) |
| `GROQ_API_KEY` | ключ Groq |

### Шаг 8. Запусти первый раз вручную

В системе **3 workflow**:
- **Generate Weekly Predictions** — генерирует свежие предсказания через Groq, обновляет `predictions.json`. Авто: воскресенье 22:00 МСК.
- **Weekly Post** — постит пост с тремя картами в канал. Авто: понедельник 9:00 МСК.
- **Daily Fact** — постит факт о случайной карте. Авто: каждый день 11:00 МСК.

Для первого теста запусти их по очереди:

1. **Actions → Generate Weekly Predictions → Run workflow → main → Run workflow**
   Сгенерирует `predictions.json` и закоммитит. Проверь, что в репо файл обновился и в нём осмысленный intro и три предсказания.

2. **Actions → Weekly Post → Run workflow**
   Опубликует пост в канал. Проверь, что:
   - В канале появился пост с картинкой трёх обложек
   - Под постом есть кнопка «🔮 Открыть расклад»
   - Клик по кнопке открывает WebApp с тремя картами
   - Тап на карту → анимация → предсказание

3. **Actions → Daily Fact → Run workflow**
   Опубликует факт о случайной карте. Проверь, что:
   - В канале появился пост с картинкой карты и любопытным фактом
   - Кнопка WebApp работает

После проверки workflow запустятся автоматически по расписанию.

## Тонкости

### Где живут предсказания?
В файле `webapp/predictions.json`. Он публичный (любой может прочитать). Это окей — никаких секретов там нет.

### Может ли пользователь "передёрнуть" и выбрать другую карту?
В текущей реализации — может: WebApp не запоминает выбор, при перезагрузке страницы пользователь снова видит три закрытые карты и может выбрать другую. Если хочешь это исправить — нужно либо добавить сохранение выбора в localStorage браузера (но это обходится очисткой кэша), либо сделать backend с базой пользователей.

На практике для канала с предсказаниями это не критично — если человек нажал «второй раз», значит, ему хотелось другого ответа. Это эмоционально, не строго.

### Почему WebApp, а не обычный бот?
Чтобы не нужен был хостинг. WebApp — это просто статическая страница, GitHub Pages раздаёт её бесплатно.

### Как менять расписание?
В `weekly.yml` и `daily.yml` есть строка `cron: "0 6 * * 1"`. Это формат cron в UTC.
- `0 6 * * 1` = 6:00 UTC = 9:00 МСК, понедельник
- `0 8 * * *` = 8:00 UTC = 11:00 МСК, каждый день

### Что делать когда устанет работать
GitHub Actions для публичных репо бесплатны без лимитов. Но если ты сделаешь репо приватным — лимит 2000 минут/мес. Нам нужно ~30 минут в месяц, всё ок.

## Проблемы и решения

**WebApp открывается, но картинки 78 карт не загружаются**
Проверь URL первой проблемной карты в браузере. Wikimedia иногда блокирует hotlinking — но в норме всё работает. Если проблема — можно скачать все 78 картинок в `webapp/images/` и поправить пути в `cards.json`.

**Groq ругается на rate limit**
Маловероятно при нашей нагрузке (10 запросов в день). Если всё-таки — увеличь `MAX_RETRIES` в скриптах или добавь задержку между запросами.

**Кнопка WebApp в посте открывает страницу как обычную ссылку, а не как Telegram WebApp**

Это значит, что в `WEBAPP_URL` лежит ссылка на github.io, а не direct link на Mini App. Перепроверь Шаг 4 — должна быть создана Mini App через @BotFather, и в `WEBAPP_URL` должна быть ссылка `https://t.me/<bot>/<app_short_name>`. Telegram распознаёт такие ссылки и открывает их inline как WebApp.

**Бот публикует пустые предсказания**
Проверь логи в Actions. Скорее всего, Groq вернул не-JSON или неправильную структуру. В коде есть `validate_response` — если падает на нём, посмотри что вернул Groq.
